# 体验质量与验证

选择与当前页面相关的项目，不机械要求所有场景通过。下表是本项目的验证方法，不是 Apple 认证清单。官方入口见 [来源索引](sources.md)。

| 方面 | 看什么 | 怎么验证 |
|------|--------|----------|
| 层级与操作 | 主任务可发现；导航与操作分开；图标有可理解名称 | 沿任务找到入口，检查可见文案与控件的实际语义 |
| 字号与布局 | Apple 动态字号或 web 文本缩放；长文案；小窗口 | 放大文字/缩窄窗口后，内容与主要操作仍可读取和使用；不以截断隐藏必要信息 |
| 键盘与读屏 | 可访问名称、角色、状态；焦点顺序与恢复 | 只用键盘完成主路径；读屏确认标签、错误和结果；关闭弹层后焦点合理返回 |
| 颜色与材质 | 状态不只靠颜色；亮暗外观；背景变化后的可读性 | 用实际前景/背景值或测量工具检查对比；不要从截图目测给出比例 |
| 动态效果 | 反馈解释发生了什么；不阻止继续操作 | 系统减少动态效果开启时仍看懂状态；关键内容不依赖动画才能获得 |
| 保存与恢复 | 进行中有反馈；失败不冒充成功；输入、重试、取消合理 | 模拟失败、重复点击与恢复；确认不会丢草稿或产生重复记录 |
| 权限 | 请求有上下文且范围必要；拒绝后能继续或理解限制 | 首次使用、拒绝、稍后重试；只有底层支持时才承诺无权限替代路径 |
| 删除 | 后果清楚；撤销或确认与风险匹配 | 验证撤销时限、恢复内容和焦点；不可恢复时验证明确告知与取消 |

## Liquid Glass 与视觉细节

先确认平台、最低版本、当前组件库和用户意图。官方将 Liquid Glass 用于导航与控件层；它不是“让所有内容透明”的理由。优先使用系统或已有组件的适配，而非叠加多层模糊。见 [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)。

评估材质时关注内容与控件的区分、移动背景上的可读性、降低透明度/提高对比度设置、性能与旧版本降级。对于 web 或 Windows，依据自身实现能力选择材质；不承诺仅靠 CSS 模糊即可获得系统行为。

间距、圆角和字号先查项目 tokens。若确实需要新数值，明确它是可试验的设计提案及适用条件；官方阈值需提供页面、单位与平台上下文。不要把 iOS 的 pt 当 CSS px 或 Windows 的有效像素直接搬用。

## 示例中的数值也是产品行为

金额、计数、进度与百分比要交叉核对，并说明舍入规则。以总额 328、小费 10%、4 人为例：小费 32.80，合计 360.80，人均 90.20。存在尾差时，需要决定分配规则，不能只让每人显示相同的四舍五入结果就宣称账目平衡。
