# 功能落位剧本（Placement Playbook）

在写输出骨架的「功能落位 / IA」与「UI 结构」前加载本文件。  
原则判断见 `eight-principles.md`；平台边界见 `surfaces.md`。

落位目标：让用户在 **3 秒内知道在哪、7 步内能完成主任务**（Simplicity + Purpose），且位置符合该表面惯例（Familiarity）。

---

## 通用落位流程

1. 列出用户任务：主任务 1 个 + 次要任务 ≤ 5 个  
2. 标频率：高频 / 中频 / 低频 / 危险  
3. 按表面选 **导航壳**（下表）  
4. 映射：高频 → 一级可达；中频 → 二级；低频 → 设置或「更多」；危险 → 有确认且勿与高频并排同形  
5. 画出区域：导航 / 主内容 / 主操作 / 辅助 / 状态  
6. 检查 Agency（撤销）与 Responsibility（权限时机）

---

## 按表面：导航壳与落点

### iOS

| 要素 | 建议 |
|------|------|
| 一级导航 | 2–5 个 Tab（同级顶级任务）；或单层列表+详情（数据型） |
| 主操作 | 导航栏尾部按钮；或主内容区明确 CTA；编辑态用上下文工具栏 |
| 返回/层级 | 推入导航栈；模态/Sheet 用于短时分支任务 |
| 搜索 | 导航区域或列表顶；结果页保持可撤销 |
| 设置 | 应用内「设置」入口（常在 Tab 或个人资料）；系统级能力才进系统设置 |
| 危险操作 | 滑动操作/菜单中的破坏项需区分强调；删除确认 |

**避免：** Tab 塞满低频项；用模态做主流程导致无法返回上下文。

### iPadOS

| 要素 | 建议 |
|------|------|
| 一级导航 | 侧边栏 + 内容列；宽屏多栏（列表 | 详情 | 检视器） |
| 主操作 | 工具栏；多选后批量栏 |
| 指针/键盘 | 提供指向目标与快捷键，不与触控互斥 |
| 多任务 | 关键流程在分屏/Stage Manager 下仍可读 |
| 设置 | 侧边栏末端或工具栏齿轮；复杂设置用独立设置列 |

**避免：** 简单放大 iPhone 单栏；忽略多选与拖放机会。

### macOS

| 要素 | 建议 |
|------|------|
| 一级导航 | 侧边栏分区；或工具栏分段 |
| 命令发现 | 菜单栏提供完整命令；工具栏放高频；快捷键服务专家 |
| 主操作 | 工具栏主按钮；面板内主 CTA |
| 多窗口 | 文档型可多窗；工具型注意单例面板 |
| 设置 | 标准设置窗口 + 侧边栏分类 |
| 右键 | 上下文菜单复现选区相关命令 |

**避免：** 无菜单等价物的「仅手势」；把移动端汉堡菜单当 Mac 主导航。

### Windows desktop

| 要素 | 建议 |
|------|------|
| 一级导航 | NavigationView / 枢纽；或顶部功能区（文档重编辑类） |
| 主操作 | 命令栏/工具栏左侧主命令；页面内主按钮 |
| 系统集成 | 标题栏、跳转列表、系统主题（亮暗）诚实响应 |
| 设置 | 应用内设置页；遵循 WinUI/Fluent 信息层级 |
| 上下文 | 右键菜单；加速键 |

**避免：** 假 iOS Tab + 大卡片堆；忽略键盘与多窗口。  
**声明：** 八原则仍用来解释这条落位；控件按 Fluent / WinUI。不是 Apple HIG 合规（见 `surfaces.md` 规则 2）。

### Android 手机

| 要素 | 建议 |
|------|------|
| 一级导航 | 3–5 个同等重要的目的地：底栏，图标加文字标签。多于 5 个不要硬塞进底栏。少于 3 个用 tabs，不要做只有一项的底栏 |
| 单任务工具 | 不用底栏。顶栏放标题和一两个动作，其余进溢出菜单 |
| 大窗口 | 底栏只适合紧凑和中等宽度。更宽时改导航轨。底栏不是桌面导航 |
| 主操作 | 填充按钮。若同时有底栏，FAB 在底栏上方靠端，且不盖住底栏 |
| 搜索 | 顶栏搜索。键盘会暂时盖住底栏，这是预期，不是把搜索做成另一个应用 |
| 设置 | 低频进溢出菜单或设置目的地。不要复制 iOS 的设置层级当 Android 习惯 |
| 返回 | 使用系统返回或顶栏返回，让用户能回到上一个上下文 |
| 危险操作 | 与主按钮不同形；说明后果。触控目标至少约 48 dp |

**避免：** 假 iOS 大标题和圆角卡片堆；给单屏计算器加五个 Tab。  
**声明：** 底栏用或不用，都要写它承接的原则（通常是 Purpose、Simplicity、Familiarity）和张力。控件按 Material。不是 Apple HIG 合规。

### 响应式网页（含 mobile web）

| 要素 | 建议 |
|------|------|
| 这是什么 | 浏览器标签里的同一网站。窄视口是 mobile web，不是 iOS 或 Android 应用 |
| 窄屏 | 单列；主任务在首屏；导航可收成页内的少量入口，仍然是网页控件 |
| 宽屏 | 稳定的页内导航 + 限制行长的正文。按内容何时难读来折行，不按某一台手机的像素 |
| 主操作 | 放在它改变的内容旁边。全页只保留一个主按钮样式 |
| 搜索 | 与内容同一路由或页内字段。不要做成系统标题栏里的搜索 |
| 设置 | 账户菜单或设置页。不是操作系统的设置窗口 |
| 键盘 | 焦点可见，顺序跟视觉一致。悬停不是唯一路径 |
| 目标与对比 | 指针目标至少考虑 WCAG 2.2 的 24×24 CSS 像素（有例外）；重要控件可以更大。正文对比按 4.5:1 这一档检查 |

**避免：** 画出 macOS 菜单栏或 Windows 标题栏当作网页的 chrome；把窄屏页面说成已经做了原生 App。  
**声明：** 浏览器栏属于浏览器。稿件里若画出地址栏，只是为了标明容器。

### Browser extension

| 要素 | 建议 |
|------|------|
| 弹窗（popup） | **单一主任务**；标题 + 简短状态 + 1 个主按钮 + 必要次要链接 |
| 侧栏（side panel） | 允许稍长工作流；仍要分段与清晰主 CTA |
| 选项页（options） | 权限说明、账户、默认值、低频配置 |
| 内容脚本 UI | 最小覆盖；不阻挡宿主关键控件；易关闭 |
| 权限 | 可选权限在用户点击需要它的动作时请求 |

**避免：** 弹窗变「迷你 App 厨房水槽」；安装时申请全部主机权限；把网站的整页信息架构塞进弹窗。  
**声明：** 弹窗只留一件事，是 Simplicity 和这个容器的 Familiarity 一起做成的，不是把原则放下。控件按扩展惯例。不是 Apple HIG 合规。扩展和上面的响应式网页是两份落位。

### Linux 桌面

先定 GNOME 或 KDE。没定就问；项目若已经用 libadwaita 或 Kirigami，用那个，不必再问一遍桌面环境。Apple 的八原则仍然要写。GNOME 更倾向让破坏性操作可撤销，Apple 的 Agency 常要求先确认：这是张力，写进取舍，不要改成其中一份规范的清单。

| 要素 | GNOME | KDE |
|------|-------|-----|
| 窗口 | 头栏即标题，关闭在右侧 | 保留用户认识的菜单和工具栏；主路径默认可见 |
| 主操作 | 放在头栏，靠近当前视图 | 默认界面里就能看见；快捷键和右键是加速 |
| 次要动作 | 渐进披露，不一次铺开 | 可以提供专家能力，但不要把「可定制」当成没做决定 |
| 危险操作 | 优先能撤销，而不是一律先确认。若仍要确认，写出为什么这里不能只靠撤销 | 确认或撤销按后果；不要只藏在快捷键里 |
| 不要 | 画成 Mac 红绿灯或 Windows 标题栏后说这是 Linux | 用一个汉堡菜单作为唯一入口 |

**声明：** 窗口 chrome 用这一列的桌面环境。八原则仍然解释为什么主操作离手近、为什么危险操作可撤销或要确认。不用 Apple HIG 或 Fluent 的控件代替这一列，也不写成 HIG 合规。两种桌面不要折中成第三种假系统。

## 功能类型 → 落点速查

| 功能类型 | iOS 手机 | Android 手机 | 响应式网页 | macOS | Windows | 扩展 |
|----------|----------|--------------|------------|-------|---------|------|
| 核心每日任务 | Tab 或首页主按钮 | 底栏目的地，或单任务顶栏 | 页内首屏 | 侧边栏首项 + 工具栏 | 导航首项 + 命令栏 | 弹窗主按钮 |
| 创建 | 导航栏动作。无中生有的 FAB 要有理由 | 填充按钮或底栏上方的 FAB | 内容旁的页内按钮 | 工具栏与「文件」菜单 | 命令栏「新建」 | 弹窗主按钮；复杂流程另开页 |
| 搜索 | 列表顶或导航 | 顶栏 | 页内字段或搜索路由 | 工具栏 | 命令栏 | 弹窗里只做短过滤 |
| 设置 | 应用内设置 | 溢出菜单或设置目的地 | 设置路由或账户菜单 | 设置窗口 | 设置页 | 选项页 |
| 危险操作 | 确认；不与主按钮同形 | 同左，目标约 48 dp | 不与主按钮同形；不只靠红色 | 菜单 + 确认 | 同左 | 弹窗内确认，或放进选项页 |

iPad、GNOME、KDE 不塞进这张窄表：iPad 用上一节的分栏；Linux 用上一节的两列。多目标产品把用到的列抄进差表，没用到的列不要填。

## 落位验收（输出前自检）

- [ ] 高频任务一级可达；危险与高频不同形  
- [ ] 设置不抢主路径，但 2 次点击内可进  
- [ ] 多表面差表已写（若适用），非复制同一线框  
- [ ] 扩展弹窗无「厨房水槽」；网页没有被写成扩展或原生窗口
- [ ] Android 单任务没有被加上 3–5 项底栏；底栏也没有被用到桌面
- [ ] 非 Apple 表面写了落位承接的原则和张力，并写了自己的控件来源；没有写成 Apple HIG 合规
- [ ] 只做手机时，差表没有桌面列
