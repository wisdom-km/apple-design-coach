# 视觉输入解读：截图 vs 线框

截图与结构化线框/画框均为一等公民输入。纯文本需求可跳过本文件。

**默认规则：** 当 **截图 + 线框同时存在** 时，先确认其用途与版本；用户对当前目标的明确说明优先。线框代表当前意图时：

1. **先对齐线框意图**（结构、主次、路径）  
2. **再用截图做现实校验**（已实现、系统 chrome、密度、偏差）  
3. 在「风险与翻译备注」写出 **意图 vs 现实** 差距表  

---

## 输入类型识别

| 类型 | 特征 | 当作 |
|------|------|------|
| 截图 | 照片/PNG 真实 UI、系统状态栏、真实字体与控件 | **现实** |
| ASCII 盒 | `+--+`、`| |`、缩进盒 | **意图线框** |
| 标注区域 | 「顶部工具栏」「列表区」「主按钮」等标签 | **意图** |
| 正式线框 | 灰盒、占位文案、无品牌抛光 | **意图** |
| 精修 mock | 高保真视觉 | **设计提案**；没有运行证据不能当作已实现现实 |

若无法判断，标为未确认的视觉材料；只有会影响结论时追问。不要仅凭高保真外观就当作已上线界面。

---

## 如何读线框（意图）

按序提取：

1. **表面暗示** — 是否画出 Tab/侧边栏/菜单栏/扩展弹窗比例？若无，用用户声明的表面补全。  
2. **区域清单** — 每个盒的名称与职责（导航 / 内容 / 主操作 / 辅助 / 状态）。  
3. **层级** — 哪一块最大、最上、最对比：那是视觉主任务。  
4. **路径** — 箭头、编号、「步骤 1/2」；无则从主 CTA 反推。  
5. **缺失** — 空态、错误、权限、设置入口是否未画（常见）→ 列入待补。  
6. **标签歧义** — 不清楚的标签先短确认；无法确认时列假设。

ASCII 解读提示：

```text
+------------------+
| nav              |  ← chrome
+------------------+
| list             |  ← 主内容
|                  |
+------------------+
| [primary CTA]    |  ← 主操作
+------------------+
```

输出时应把意图总结为：`区域表 + 主路径 + 未呈现/待确认项`。线框没画不等于产品非目标；非目标以用户约束或已确认决策为准。

---

## 如何读截图（现实）

按序提取：

1. **系统 chrome** — 状态栏、标题栏、手势条、浏览器工具栏、扩展弹窗边界。  
2. **已实现导航** — 当前 Tab/侧边栏选中项、栈深度线索（返回标题）。  
3. **密度与层级** — 是否拥挤、主 CTA 是否淹没、对比是否足够。  
4. **文案与状态** — 加载中/空/错误是否诚实；权限拒绝是否可见。  
5. **平台一致性** — 控件是否像该表面原生；是否假 iOS 皮。  
6. **可访问线索** — 目标过小、仅靠颜色区分、截断文案等风险。

截图只支持画面可见内容及其拍摄时的状态，不能证明完整产品意图、交互行为或其他页面。键盘导航、读屏标签、精确对比度、动态字号和恢复路径需要代码、测量或运行验证；看不到图时不能假称已看。

## 双输入对齐流程（线框为当前意图时）

```text
线框意图 ──总结──► Intent Model（IA + 主路径 + 区域职责）
                         │
截图现实 ──对照──► Reality Check
                         │
                   Gap List（多/少/错位/平台违和）
                         │
                   结合当前用户要求与约束；用 Gap 驱动改版建议
```

差距表模板：

| 项目 | 线框意图 | 截图现实 | 建议 |
|------|----------|----------|------|
| 主导航 | … | … | 保留意图 / 或因平台约束改壳 |
| 主 CTA | … | … | … |
| 设置入口 | … | … | … |
| … | … | … | … |

**冲突裁决：**

- 意图清晰且符合声明表面 → **改现实就意图**  
- 意图违反表面硬约束（如扩展弹窗塞满桌面级 IA）→ **改意图就表面**，并在备注说明  
- 意图模糊 → 先补问或列假设，再落合同  
- 用户说明线框过时 → 不把旧结构强加给当前截图；只提取仍有效的目标

---

## 仅有截图

1. 反推可能意图（带置信度）  
2. 用八原则诊断现实问题  
3. 提出「重设计合同」——明确哪些现实可留作 Familiarity，哪些必须改  

## 仅有线框

1. 补全未画状态与权限  
2. 按表面做落位翻译（可能线框画的是错误壳）  
3. 给线框级修订，不要求精修  

## 仅有文本

1. 跳过视觉对齐  
2. 直接合同 → 落位 → 结构（可用 ASCII 产出线框级结构）  

---

## 参考图输出标准（教练侧）

- 交付 **线框级方向**：区域、标签、主路径箭头、状态标注  
- 不交付：视觉抛光、假数据海报、无依据的 pt/圆角规范  
- 双输入时：可并排「意图结构 | 现实问题 | 建议结构」三列文字/ASCII  

---

## 常见误读（避免）

1. 把截图里的临时实验 UI 当成最终意图  
2. 把线框里的占位拉丁文当真实文案层级  
3. 忽略截图中的系统安全区/扩展裁切，提出不可实现的布局  
4. 双输入时只「修图」不「护意图」  
5. 对 Windows/扩展截图仍按 iOS 间距与导航开药方
