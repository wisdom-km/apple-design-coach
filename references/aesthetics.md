# 视觉方向（具体，但不编造规范数字）

写「UI 结构」时一起写。用户没要可视草稿时，也要给出能执行的视觉方向。用户要了草稿时，草稿必须遵守这里的方向，而不是另起一套装饰。

官方数字只在 `source-provenance.md` 有出处时使用，并写出来源。项目自己定的字号、间距、色值，标明「项目决定」或「示例决定」。不要把示例决定说成 HIG、Material 或 Fluent 的测量值。

---

## 方向要成套

一次只定一套，并说明它如何服务主任务：

1. **字体角色**：该平台的系统字体优先。至少区分正文、次要说明、主结果或标题。用字重和字号建立层级，不靠把每块都放进卡片。
2. **间距节奏**：选定一个重复的间距。若用 4 或 8 的倍数，那是项目决定，除非某条官方指南明确写了这个数。不把 8 的倍数或某一条 16px 边距写成所有平台的规定。
3. **密度**：手机留出触控间距；桌面可以更密，但层级仍要一眼可读；扩展弹窗最紧，只留主任务。密度跟着会话长度走，不跟着「看起来高级」走。
4. **颜色角色**：背景、表面、主文字、次文字、一个强调色、一个危险色。强调色只用在主操作和当前选中。危险操作不与主按钮同形同色。不要只靠颜色区分状态。
5. **层级**：最大的、最对比的、最靠近主路径的，是主任务。其余降级，而不是等权排列。

避免这些没有任务理由的套路：等大卡片叠卡片、每块一个状态标签、渐变色块加口号、所有按钮一样重、首屏堆满字段。

## 方向确认之后，把成稿做完

方向还在选时，轻量小样就够。方向已经确认、而且用户要看设计稿时，下面这些做法用来把那一套方向画完。它们不是新的提问，也不是某一本账本的固定版式。

先给一帧主界面。覆盖说明和状态对照放在这一帧后面。设备框若要画，用细线。框和说明不能比内容更响。ASCII、着色线框、多只粗框并排的说明书，不能叫做这一帧。

1. **文本和数字用角色。** 先定主结果、标题、正文、次要说明，再用字号和字重分开。Apple 表面用系统的 text styles。Android 用 Material 的 Display、Headline、Title、Body、Label 这些角色；具体 sp 以组件库文档为准，不要把最大的 Display 用到密表首页。没有官方像素时，把字号写成项目决定，并写它起什么作用。
2. **一列数字要稳。** 金额和数量用等宽数字（`tabular-nums`），在同一列对齐。币种用短标签或符号。不要只靠颜色区分收入和支出。
3. **密度跟着选定的方向。** 密的列表用分隔线、对齐和重复的行距。不要改成等权卡片、大留白或玻璃渐变来逃避这一套方向。
4. **长内容重排。** 空间变紧或字号变大时，横向并列改成上下，或列表行限制行数、全文放到下一屏。长标题不能把数字列挤乱，也不能让全文只存在于被截断的那一行。
5. **对齐和光学。** 一组图标和相邻文字用接近的字重。图标需要时加内边距，而不是只按几何盒子居中。
6. **动作分主次。** 顶栏的搜索、更多用图标，或图标加更轻的标签，不要和标题同一字重。主操作一个填充。危险操作不同形。溢出菜单在空白和失败里也要看得出里面是什么。
7. **三层分开。** 内容是第一眼。控件是功能层。手机框、假浏览器边和说明文字是外壳。
8. **颜色表示角色。** 强调色只给主操作和当前选中，上面的文字单独配对比。危险色不借用主操作的填充。项目色值写进已有的设计记录，不另建一套 token 库。

中文不要套用为拉丁文设计的强负字距。加载中的占位跟列表同一节奏，不用一颗看起来能点的主色按钮代替骨架。演示文稿的封面和超大事实页不是应用首页。出处和哪些不搬，见 `source-provenance.md`。

### 六步把这一帧排完

方向已经确认、而且要看界面时，按这个顺序做。它不替代方向选择，也不把某一本账本的尺寸写成所有应用的规定。关系写进项目已有的设计记录，不另建一套。

1. 锁住文案、数据、方向和字体条件。示例数据保持标成示例。不要为了排齐改短唯一的一句。
2. 先定内容框、安全区和背景能铺到哪里。写明哪一层负责边距。背景满宽不等于文字贴边。安全区不要在父层和子层各加一次。
3. 按角色定锚点。同一角色共用主前缘。从属内容可以再缩进。数字共用后缘。需要时写明基线跟谁。标题、主结果、正文、辅助和操作用成套的字号、字重和行高。同组比组间更紧。重复的行用同一节奏。间距不必全部相等。
4. 主屏的骨架复用到状态。空白、失败和说明里的同一组件，用同一套边，不另起坐标。
5. 在真实要展示的宿主里渲染主帧、至少一个复用了该骨架的状态，以及最危险的一种窄宽或长中文放大。HTML 里放大字号不是系统字体缩放，也不是真机。
6. 看到偏差就改同一份稿，再回到同一位置看。记下位置与可见现象、负责的那一层、改了什么、同位置的证据。

修复先动容器、级联和约束，再动文字角色和换行，最后才做字形光学。不用多处负 margin，也不用 `!important` 把被盖住的边距补回去。说明样式只管说明。应用角色只管应用。

这些不是错位：图标槽比正文更靠左，子说明的刻意缩进，分隔线或背景铺到内容框以外。这些才是错位：同一角色的前缘在主帧和状态帧里无故分开；大号数字整段离开内容框。字形侧边的一点光学差，不是整段离开。

可迁移的反例：用各自的 em 把不同字号的横 margin 凑成同一距离，后面一条更具体的 `p` 规则再用 margin 简写把左右清零，并改掉行高和颜色。顶栏的 padding、行容器的 margin、说明块的 padding 可能还在，于是段落凸出去，列表仍缩进。打开的第一帧如果在那条规则外面，它本身没有被污染。不要把每一帧都说成同样错了。写在说明容器里的重复帧和状态帧仍要量。

演示可以借母版、对齐参照和少量版式家族。不把幻灯片的超大事实页套成密表。

## 有出处的尺寸（引用，不要扩写）

下列数字在 2026-11-17 核对过对应页面。例外和上下文以原页为准，这里不复制整节。

| 用途 | 数字 | 出处 |
|------|------|------|
| iOS / iPadOS 按钮热区的一般规则 | 至少 44×44 pt | Apple HIG Buttons |
| iOS / iPadOS 控件 | 默认 44×44 pt，最小 28×28 pt | Apple HIG Accessibility |
| macOS 控件 | 默认 28×28 pt，最小 20×20 pt | 同上 |
| iOS / iPadOS 自定义文字 | 默认 17 pt，最小 11 pt | 同上 |
| macOS 自定义文字 | 默认 13 pt，最小 10 pt | 同上 |
| Android 可交互目标 | 至少 48×48 dp；视觉更小的控件要靠内边距补足目标，并避免目标重叠 | Android Accessibility Help；Jetpack Compose Material 3 的最小交互尺寸 |
| 网页指针目标 | WCAG 2.2 AA：至少 24×24 CSS 像素，另有间距等例外；AAA：至少 44×44 CSS 像素，例外更少 | W3C WCAG 2.2 |
| 网页正文对比 | WCAG 2.2 AA：普通文字至少 4.5:1，大号文字至少 3:1 | 同上 |

Windows 本轮没有找到一条可以当成「最小点击像素」来引用的官方数字，所以不写。桌面 Windows 跟随 WinUI 控件的尺寸，键盘和指针路径都要在。

Apple 还写到：有边框的控件周围大约 12 pt、没有边框的大约 24 pt，能降低误触。这是 HIG 的经验说法，不是本仓库另定的网格。

## 输入和窗口

- **触控**：主操作放在拇指或手容易够到的一边，目标用上表里该平台的尺寸。相邻目标留出空隙。
- **指针和键盘**：桌面和网页的主任务不能只放在悬停里。焦点要看得见。高频命令可以有快捷键，但快捷键不是唯一入口。macOS 的完整命令进菜单栏；Windows 的命令进命令栏、菜单或上下文菜单；网页的命令留在页面里，不假装拥有系统菜单栏。
- **响应式窗口**：窄了就重排，而不是把手机画面放大。阅读用的正文限制行长。宽窗口把导航固定下来，把主内容让出来。
- **系统 chrome**：状态栏、标题栏、菜单栏、浏览器工具栏不属于应用内容。网页草稿可以画出浏览器栏，用来表明「这是网站」；原生草稿画出该系统的窗口栏。不要两套一起画在同一个窗口里冒充一种应用。
- **无障碍**：文字能放大时布局仍成立；不只用颜色；图片按钮有文字标签或可访问名称。权限、空、加载、错误、离线按任务需要覆盖。某项确实没有（例如纯本地计算没有加载），写「不适用」和原因。

## 和极简的边界

简洁是去掉不服务主任务的摩擦，不是把功能藏起来。高频保留在一级；中频进二级；低频进设置；危险操作分开，并提供撤销或确认。藏进一个菜单又称为简洁，是反模式。

GNOME 的指南更倾向让破坏性操作可以撤销，而不是一律先弹确认。Apple 的 Agency 则要求破坏性操作先确认。目标是 GNOME 时，把这个张力写进取舍，不要无声地套用 iOS 确认框。KDE 要求常见路径在默认界面里看得见，专家快捷键是加速，不是唯一入口。
