# B 层：表面适配（Surfaces）

哲学内核（A 层）跨表面共享；**表现与 chrome 必须按表面翻译**。

官方 Apple 原则（仅适用于理解精神；非 Apple 表面不得声称 HIG 合规）：

- https://developer.apple.com/design/human-interface-guidelines/design-principles
- https://developer.apple.com/videos/play/wwdc2026/250/

可扩展：新增表面时，补一行对比表 + 一节「习惯来源」，仍走「精神借用、本地惯例」规则。

## 翻译规则（A → B）

### 规则 1：意图不变，容器变

同一 Purpose / IA 意图，换成该表面的导航壳与主操作位置。  
例：「查看列表 → 打开详情 → 编辑」在 iOS 用推入导航；在 macOS 用列表+详情分栏；在扩展里可能拆成「弹窗列表 → 选项页详情」。

### 规则 2：精神借用，不借皮肤

非 Apple 表面可借用：

- 清晰目的、用户控制、晚请求权限、宽恕、层级清楚、细节诚实

不可借用（作为默认外观）：

- iOS Tab Bar / Large Title / 过多圆角卡片堆叠冒充「高级」
- 把 SF Symbols 审美当 Windows/扩展的唯一图标语言而不考虑系统图标

输出中必须写一句：

> 本方案在 {Windows|扩展} 上借用 Apple 设计原则之精神（Purpose/Agency/…），**不声称符合 Apple HIG 合规**；控件与导航遵循 {Fluent/WinUI|浏览器扩展} 惯例。

### 规则 3：平台优势优先（Flexibility）

| 表面 | 优先发挥 |
|------|----------|
| iOS | 快速触达、手势、专注单任务 |
| iPadOS | 分栏、拖放、指针精度 + 触控 |
| macOS | 键盘、多窗口、菜单发现性、深度工作流 |
| Windows | 多窗口、跳转列表/系统集成、键鼠效率、系统主题 |
| Extension | 宿主上下文、最小打扰、即时动作 |

### 规则 4：密度与会话长度匹配（Simplicity）

扩展弹窗：默认 **一个主任务**；次要能力进选项页。  
桌面：允许更高信息密度，但层级仍须一眼可读。  
手机：先主任务，渐进披露。

### 规则 5：权限按表面模型翻译（Responsibility）

- Apple：用途说明 + 情境化请求 + 系统设置深链  
- Windows：能力声明 + 系统隐私页引导 + 应用内解释  
- Extension：`permissions` / optional permissions；在用户触发需要该能力的动作时再请求；避免安装时一口吃光

### 规则 6：一致性按表面边界定义（Familiarity）

- 先与 **该 OS/浏览器惯例** 一致  
- 再与 **自家产品在该表面内** 一致  
- 最后才考虑跨表面「品牌感」（颜色/语气），而非复制布局

### 规则 7：可扩展表面模板

新增表面 `X` 时填写：

1. 输入方式与会话长度  
2. 导航壳与设置入口  
3. Familiarity 权威来源（官方 UX 指南链接若有）  
4. 与本产品其他表面的翻译差异  
5. 明确：是否声称任何 HIG/其他合规（默认否，除非该表面就是 Apple）

## 多表面产品策略

1. 先写 **共享设计合同**（Purpose、对象、成功标准、非目标）  
2. 再为每表面写 **落位差表**（同一功能：入口在哪、主按钮在哪、设置在哪）  
3. 禁止「一份线框打天下」；允许共享组件库，但 chrome 分叉  

差表最小字段：`功能 | iOS | iPadOS | macOS | Windows | Extension | 备注`
